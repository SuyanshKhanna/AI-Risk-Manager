ISSUE 30: Frontend Live Predictor Display & Logic Bugs
===========================================================
  ├─ Symptoms: 
  │   - The score on the live demo predictor showed double percentage signs (e.g., 86%%)
  │   - The model output was identical for every request, regardless of form input.
  │
  ├─ Root Cause:
  │   - Double `%` was caused by the JS logic appending `%` in `animateCounter()` on top of a hardcoded `%` in the HTML markup.
  │   - The static prediction was caused by a frontend logic bug: `Object.assign(payload, defaults, payload)`. This effectively wiped all form user inputs (`payload`) by overwriting them with `defaults`, and then copying the wiped data back onto itself. Thus, the backend always evaluated an identical set of default values.
  │
  ├─ Fix Applied:
  │   - Refactored frontend JS to not pass `%` to `animateCounter`, and removed erroneous `+` sign parsing. 
  │   - Fixed payload object merging: `const finalPayload = Object.assign({}, defaults, payload)`.
